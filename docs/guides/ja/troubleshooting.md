Hikidashi についての質問のほとんどは、`null` や空のリストについてです。どの関数も、答えられないときにだけそれを返し、リファレンスの各ページには、それがどんなときかが正確に書いてあります。このページでは、最初によく出る場合をまとめています。

## 元号の年が null になるのはなぜ？

`parseEraYear` は、その元号にあった年を表していない文には `null` を返します。

- **元号がすでに終わっている。** 昭和は64年まで、平成は31年まで、大正は15年まで、明治は45年までです。平成32年は `null` で、その年は令和2年です。
- **明治より前の元号。** 分かるのは近代の五つの元号だけで、慶応4年は `null` です。
- **ほかのものが入っている。** 月や日（令和6年5月1日）、前後の言葉（生年：昭和60年）、余分な文字があると `null` になります。先に年の部分だけを取り出すか、`YYYY-MM-DD` 形式の日付なら `eraOnDate` を使ってください。
- **今の元号で 99年を超えている。** 令和100年は打ち間違いとみなします。

```ts
import { parseEraYear } from "@johnmorrisdotca/hikidashi/wareki";

for (const text of ["平成32年", "慶応4年", "令和6年5月1日", "令和６年", "Shōwa 64"]) console.log(text, parseEraYear(text)?.westernYear ?? null);
```

## 1989年に元号の年が二つあるのはなぜ？

実際に二つあったからです。1月7日までは昭和64年、1月8日からは平成元年でした。`eraYearsOf` は新しいほうを先にして両方を返し、`eraYearOf` は新しいほうを選びます。日付が分かるなら、`eraOnDate` が正しいほうを返します。1912年、1926年、2019年も同じです。

## Date の元号がずれるのはなぜ？

`eraOnDate` は `Date` を、それ自身のタイムゾーン、つまり実行しているマシンのタイムゾーンで表した日付として読みます。東京の午前0時に作った `Date` は、UTC のサーバーでは前の日になります。タイムゾーンが問題になるときは、日付を `YYYY-MM-DD` の文字列で渡してください。

## 数が null になるのはなぜ？

`parseJapaneseNumber` は、正確に読めないものはすべて受け付けません。

- **全角のカンマ。** 「１２，０００」は `null` です。読めるのは半角の三桁区切り（12,000）と、区切りのない全角数字（１２０００）です。入力に「，」が入るなら、先に「,」に置き換えてください。
- **並んだ漢数字。** 年をときどき「二〇二四」のように一桁ずつ書くことがありますが、今は受け付けません。漢数字は単位といっしょのとき（二千二十四）だけ読み、「〇」は位としてだけ読みます（「二〇」は 20）。一桁ずつ書いた数を読むことは README のロードマップにあります。それまでは数字を使うか、元号の年なら `parseEraYear` を使ってください。
- **単位だけ、または順序が逆の単位。** 「万」だけ、「万億」など。
- **符号、小数点、9,007,199,254,740,991 を超える数。**

```ts
import { parseJapaneseNumber } from "@johnmorrisdotca/hikidashi/numerals";

for (const text of ["１２，０００", "12,000", "二〇二四", "二〇", "万", "1.5"]) console.log(text, parseJapaneseNumber(text));
```

## dictionaryForms が実在しない語を返すのはなぜ？

辞書を使わずに、書かれた語のもとになりうる辞書形をすべて挙げるので、候補の中には実在しない語もあります。「食べる」からは、「食べる」自身と並んで「食ぶ」（五段）が出ます。手元の辞書にその種類の語として載っている候補だけを、`wordClassesOf` を使って残してください。[貼り付けた文から取り出すやり方](extract-words-from-a-paste.md)で、最初から最後まで説明しています。

## extractFromText で単語が見つからないのはなぜ？

- **`known` を渡していない。** 辞書がなければ、漢字しか見つかりません。
- **単語は `known` にあるが、辞書形ではない。** `known` には辞書と同じ形で載せます。「行きます」ではなく「行く」です。
- **`known` の動詞に種類がない。** `["行く", []]` は書かれたままの「行く」には一致しますが、「行きます」には一致しません。活用した形が一致するのは、辞書がその種類の動詞だとしている語だけです。種類は `wordClassesOf` で入れてください。
- **単語が 8文字より長い。** `EXTRACT_LIMITS.wordLength` です。

## 「行く」ではなく「行き」が返るのはなぜ？

後ろに、それを動詞にするものがないからです。「東京行きの電車」の「行き」は名詞で、「行きます」の「行き」は動詞です。辞書に載っていれば、書かれたままの語を残します。ただし、動詞の語幹にしか付かない語尾（「ます」「たい」など）が続くときは別です。

## TypeScript が "@johnmorrisdotca/hikidashi/wareki" を見つけられない

エントリーポイントは `package.json` の `exports` で宣言していて、TypeScript がこれを読むのは `"moduleResolution"` が `"bundler"`、`"node16"`、`"nodenext"` のどれかのときだけです。古い `"node"`（`node10` とも呼びます）では読みません。`tsconfig.json` で三つのうちのどれかを指定してください。

## require() が失敗する

このパッケージは ES モジュールです。Node 22.12 以降なら `require` で読み込めます。それより古い Node 22 では `import`（CommonJS なら `await import(…)`）を使ってください。Node 20 以前には対応していません。

## Deno や Bun で動く？

言語の機能しか使っていないので、おそらく動きますが、どちらもテストしていません。動作したかどうかの報告は [issue](https://github.com/johnmorrisdotca/hikidashi/issues) で歓迎します。

## デモやこのドキュメントの日本語は確認されている？

まだ日本語を母語とする方には確認してもらっていません。このドキュメントの日本語は、公開する前に意味と自然さを確かめていますが、日本語のページにはどれも、まだ母語話者の確認を受けていないことを書いています。間違った文や不自然な文は、[翻訳の訂正の issue テンプレート](https://github.com/johnmorrisdotca/hikidashi/issues/new?template=fix-a-translation.md)で知らせてください。
